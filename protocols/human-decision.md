# protocols/human-decision.md — Human Decision Required

> 遇到以下情况，停止自主推进，回报用户，不自己猜。

> **CNF-4 继承声明**：决策词 `ASK` / `ESCALATE` / `DENY` 等**继承 Agent OS DECISION-PROTOCOL 唯一词汇表**，
> 本文件不重新定义决策词，只列出软件开发领域「何时必须询问用户」的触发条件。
> 回报格式（问题/原因/可选方案/推荐/需要你决定）是 DT 领域约定。

## 1. 触发条件（集中清单）

| # | 场景 | 说明 |
|:--|:--|:--|
| 1 | 需求不明确 | COMPLEX 任务 IDEAL 缺失 / 冲突 |
| 2 | IDEAL 冲突 | IDEAL 内部矛盾，或无法安全实现 |
| 3 | 重大架构问题 | 需重新设计产品方向 |
| 4 | 用户已有修改可能被覆盖 | 见 `git-workflow.md` |
| 5 | 破坏性 Git 操作 | force push / reset / 改历史 |
| 6 | 需要 Secret / API Key / 权限 | 无法自行获取或不应自行处理 |
| 7 | 无法确定正确实现 | 多方案实质产品差异 |
| 8 | 多方案有实质产品差异 | 用户应知情选择 |

## 2. 回报格式

```
问题：<问题描述>
原因：<为什么不能自行决定>
可选方案：
  A. <方案 A>
  B. <方案 B>
推荐：<推荐方案 + 理由>
需要你决定：<明确列出需要用户拍板的点>
```

## 3. 原则

- **不因为自主性而让 Agent 猜测用户意图**。
- **不因为要完成任务而偷偷改变 IDEAL**。
- 小问题（字段命名、默认值）自行假设并记录，不升级。
- 只有重大未知才 HUMAN_DECISION_REQUIRED。

## 4. 与 Result Closure 的关系

- HUMAN_DECISION_REQUIRED 是少数「允许打扰用户」的场景之一。
- 其余内部开发结果不默认 announce 给用户。
